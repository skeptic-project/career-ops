# Task 001.01: Persist Extracted JD Markdown

## Epic

[Epic 001: Persist Job Descriptions and Link Them Across Career-Ops](001-jd-persistence-pipeline-integrity.md)

## User Story

As a career-ops user, I want every scanned or URL-evaluated job description saved as a local Markdown file so future reports and tracker rows can point to the exact JD that was evaluated.

## Requirements

- Create `jds/` if it does not exist.
- Generate deterministic slugs from company and role: `jds/<company-name>-<role>.md`.
- Save the extracted job description for:
  - `career-ops scan`
  - `career-ops <job-description-url>`
- Include source metadata in the Markdown file:
  - Company
  - Role
  - Source URL
  - Date captured
  - Extraction method, if available
- Avoid overwriting a materially different JD without either versioning or deterministic conflict handling.

## Acceptance Criteria

- Running scan or URL auto-pipeline stores a readable Markdown JD under `jds/`.
- Re-running the same posting is idempotent.
- The stored JD contains enough metadata to trace the source URL and capture date.
