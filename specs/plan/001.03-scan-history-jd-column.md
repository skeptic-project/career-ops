# Task 001.03: Add JD Path to Scan History

## Epic

[Epic 001: Persist Job Descriptions and Link Them Across Career-Ops](001-jd-persistence-pipeline-integrity.md)

## User Story

As a user reviewing scan history, I want each discovered job to include the local JD path so deduplication and audit trails can connect history rows to evaluated content.

## Requirements

- Add a `jd_path` column to `data/scan-history.tsv` if no equivalent column exists.
- Write `jds/<company-name>-<role>.md` for new scan-history rows.
- Keep old scan-history files readable if they do not have the new column.
- Update scan-history parsing, writing, and dedup logic to preserve the new column.

## Current Format

`scan.mjs` currently writes:

```tsv
url	first_seen	portal	title	company	status	location
```

The new format should append `jd_path` as column 8 to preserve the existing first 7 columns:

```tsv
url	first_seen	portal	title	company	status	location	jd_path
```

## Implementation Notes

- Update `formatScanHistoryRow(offer, date, status)` to append `offer.jdPath || ''`.
- Update the fresh-file header in `appendToScanHistory()`.
- Keep `loadSeenUrls()` backward compatible by continuing to read `url`, `first_seen`, and `status` by position.
- Update `detect-reposts.mjs` only if it assumes a maximum column count; it should continue to group by company/title.
- Update `openrouter-runner.mjs` fallback/default scan-history header if it writes or seeds this file.
- Add tests beside existing scan-history row-shape checks in `test-all.mjs`; expected column count becomes 8 for new rows and legacy 7-column rows remain accepted.

## Acceptance Criteria

- New scan-history rows include `jd_path`.
- Existing scan-history rows without `jd_path` do not break scanner behavior.
- Repost detection and dedup checks continue to work after the schema change.
- Spreadsheet formula protection and newline/tab sanitization still apply to all fields.
