# Task 001.05: Add JD Column to Applications Tracker Merge

## Epic

[Epic 001: Persist Job Descriptions and Link Them Across Career-Ops](001-jd-persistence-pipeline-integrity.md)

## User Story

As a user reviewing `data/applications.md`, I want a `JD` column after `Report` so each tracker row links to the local Markdown job description.

## Requirements

- Update tracker header to:

```markdown
| # | Date | Company | Role | Score | Status | PDF | Report | JD | Notes |
```

- Store JD paths relative to `data/applications.md`, for example:

```markdown
../jds/<company-name>-<role>.md
```

- Update `merge-tracker.mjs` parsing and writing to handle the `JD` column.
- Update any tracker parsers, validators, and migration utilities that assume the old column layout.
- Preserve old tracker rows without JD by leaving the cell blank or migrating when a local JD can be inferred.

## Acceptance Criteria

- `merge-tracker.mjs` writes `JD` after `Report`.
- `verify-pipeline.mjs` accepts the new tracker shape.
- Existing trackers can be migrated or read without data loss.
- Report links and JD links are normalized relative to the tracker file location.
