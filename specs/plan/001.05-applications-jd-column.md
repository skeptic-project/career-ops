# Task 001.05: Add JD Column to Applications Tracker Merge

## Epic

[Epic 001: Persist Job Descriptions and Link Them Across Career-Ops](001-jd-persistence-pipeline-integrity.md)

## User Story

As a user reviewing `data/applications.md`, I want a `JD` column after `Report` so each tracker row links to the local Markdown job description.

## Requirements

- Update tracker header to:

```markdown
| # | Date | Company | Role | Score | Status | PDF | Report | JD | Notes |
```

- Store JD paths relative to `data/applications.md`, for example:

```markdown
../jds/<company-name>-<role>.md
```

- Update `merge-tracker.mjs` parsing and writing to handle the `JD` column.
- Update any tracker parsers, validators, and migration utilities that assume the old column layout.
- Preserve old tracker rows without JD by leaving the cell blank or migrating when a local JD can be inferred.

## Implementation Notes

- Update `tracker-parse.mjs`:
  - add `jd` to `LEGACY_COLMAP` only if the canonical default tracker is migrated;
  - add `jd` to `HEADER_ALIASES` either way;
  - have `parseTrackerRow()` return `jd` when the column exists.
- Update `merge-tracker.mjs`:
  - parse `addition.jd`;
  - normalize JD paths relative to `TRACKER_DIR`, similar to report link normalization;
  - include `jd` in `buildRow()` for trackers whose header includes a JD column;
  - preserve existing JD on duplicate updates when the incoming addition has no JD.
- Update `verify-pipeline.mjs`:
  - add `jd` to its header aliases or refactor to import `tracker-parse.mjs`;
  - verify JD links resolve from the tracker directory, with repo-root fallback for transition.
- Update mutating/read scripts that use shared tracker parsing or row rebuilds:
  - `dedup-tracker.mjs`
  - `normalize-statuses.mjs`
  - `analyze-patterns.mjs`
  - `followup-cadence.mjs`
  - `tracker.mjs`
- Update default tracker creation wherever the header is hard-coded, including onboarding docs and `tracker.mjs`.
- Extend `tracker-columns-tests.mjs` and `test-all.mjs` with a tracker that includes both optional `Location` and `JD` columns.

## Acceptance Criteria

- `merge-tracker.mjs` writes `JD` after `Report`.
- `verify-pipeline.mjs` accepts the new tracker shape.
- Existing trackers can be migrated or read without data loss.
- Report links and JD links are normalized relative to the tracker file location.
- Duplicate updates preserve JD links and never shift `Notes` into the wrong column.
