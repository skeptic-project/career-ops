# Task 001.04: Carry JD Path Through Tracker TSV Generation

## Epic

[Epic 001: Persist Job Descriptions and Link Them Across Career-Ops](001-jd-persistence-pipeline-integrity.md)

## User Story

As the pipeline records evaluated jobs, I want tracker-addition TSV rows to include the local JD path so `merge-tracker.mjs` can write it into `data/applications.md`.

## Requirements

- Extend tracker-addition TSV generation to include JD path.
- Preserve compatibility with current TSV rows:
  - Existing 9-column format should still merge.
  - New format must be 10 columns with `jd` after `report` and before `notes`.
- Update documentation in `AGENTS.md` or the relevant mode files once implementation happens.
- Ensure generated JD paths are root-relative before merge, similar to report links.

## TSV Format

Current standard:

```tsv
num	date	company	role	status	score	pdf	report	notes
```

New standard:

```tsv
num	date	company	role	status	score	pdf	report	jd	notes
```

`jd` should be root-relative when written by workers, for example:

```text
jds/atlan-engineering-manager.md
```

## Implementation Notes

- Update every TSV producer, including:
  - mode instructions in `modes/_shared.md`, `modes/oferta.md`, and `modes/auto-pipeline.md`;
  - batch worker prompt in `batch/batch-prompt.md`;
  - scripted evaluators such as `gemini-eval.mjs` and `openrouter-runner.mjs` if they write tracker-addition TSVs.
- Update `merge-tracker.mjs parseTsvContent()` to distinguish:
  - 8/9-column legacy rows without JD;
  - 10-column rows with JD before notes;
  - optional location handling without misreading JD as location.
- Keep pipe-delimited compatibility if still supported by `merge-tracker.mjs`.

## Acceptance Criteria

- New tracker-addition TSV rows carry a JD path.
- Old TSV additions still merge without a JD value.
- Pending and merged TSV directories remain valid after the schema change.
- Regression tests prove legacy 9-column rows, 10-column JD rows, and optional location rows do not shift score/status/report/notes.
